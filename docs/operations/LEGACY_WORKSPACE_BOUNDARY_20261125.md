# Legacy workspace boundary — staged only

Based on #76. Only the configured Vinhomes Saigon Park project route mounts the existing legacy App and auxiliary runtimes. Other project Overview remains the existing wireframe, and Detail displays an explicit unconfigured notice instead of the VSP editor. Hub does not mount the legacy editor. Invalid project routes do not activate the default project's editor. VSP Overview/Detail/landing retain the current layout and runtime while the VSP route is active. Switching away unmounts the editor; unsaved in-memory imports or transient state may need reconnecting when returning. This is a deliberate isolation boundary, not a complete implementation of additional projects.

Stop the two old automatic import-time migrations that removed house assignments and old anchor layout. Existing data is retained, not rewritten or moved; prior deleted data is not restored by this change. Future migration requires explicit preview and approval. Catalog generation and CSV fallback remain intact. Cloud bootstrap is still configured per build and same-origin storage is not a security boundary between users; true dynamic per-project cloud sync, scoped editor consumers, independent media/locator profiles, authorization, and full cross-project UI tests remain future work.

Unit tests check policy and invalid route decoding. Chromium uses synthetic saved keys, verifies direct and in-app foreign project navigation, checks that the legacy editor is absent and saved VSP values are unchanged. All existing QA gates remain. No actual user backup, Azure calls, original images/PDF changes, CSS redesign, production merge or deployment. Keep #76 unchanged for rollback.
