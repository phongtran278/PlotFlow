# Cloud project scope and QA runner maintenance

Stacked on #75. Legacy cloud shared keys remain owned by vinhomes-saigon-park; other project IDs can synchronize only their exact scoped prefix. No rename or migration of existing VSP keys. Validate project, schema version and storage string values before applying a cloud snapshot or recording its ETag. Block writes after failed/invalid loads, including missing legacy blob; do not auto-publish local data when a remote snapshot has no owned keys. Preserve unknown remote keys in both transport payloads. Legacy URL mode is limited to VSP. Context permits legacy fallback only for VSP.

Tests exercise pure scope, snapshot and merge policy on synthetic fixtures. The QA workflow uses Node-24 action runtimes checkout v5, setup-node v5 and upload-artifact v6, retains Ubuntu 24.04, existing browser tests and audit gates. These are targeted compatibility upgrades, not the latest major releases. Production deployment workflow and older Draft workflows are not changed.

Limitations: this is a cloud ownership guard, not complete multi-project runtime isolation. App, PosterCanvas, FineTune, asset catalog migration and other legacy DOM/localStorage consumers still need coordinated scoping and project-switch tests. Cloud bootstrap is build-time project configured, not dynamically multi-project. No real state read/write tests. Backup configuration/version history observed in portal, but actual isolated Azure restore not yet verified; no backup content, IDs, URLs or hashes from customer data committed. No Azure writes, original assets/PDF changes, production deployment or merge. Keep #75 for rollback.
